# Data Model: Adopt Shared Container Image Cleanup

No application data is created or stored. The model below describes the registry state the cleanup reasons over and the configuration it consumes, so tasks and review can check the eligibility rule consistently.

## Entities

### Package version (GHCR, read/deleted)

| Field | Meaning |
|-------|---------|
| `id` | Package version ID (numeric). Summary counts are over unique IDs, not tags. |
| `tags[]` | Zero or more tags. Untagged versions have none. |
| `updated_at` | Timestamp compared to the cut-off (tool default `updated_at`). |
| `parent/child` | Multi-arch index and its child manifests; children of a retained parent are protected by the tool. |

**Package**: `ghcr.io/linuxfoundation/lfx-self-serve`, account `linuxfoundation` (organization).

### Protected tag pattern (configuration)

Negative patterns (`!pattern`) given to the tool; a version carrying *any* matching tag is protected.

| Pattern | Source | Protects |
|---------|--------|----------|
| `!development` | caller `image-tags` | current default-branch build tag (LFX convention) |
| `!latest` | caller `image-tags` | latest tag backstop |
| `!*.*.*` | caller `image-tags` | three-segment release tags (no `v` prefix) |
| `!*.*` | caller `image-tags` | two-segment release tags |
| `!ui-pr-<N>` | generated by shared `preview-tags` job | image of each open PR labeled `deploy-preview` |
| `!main` | appended by shared workflow | default-branch tag |

### Caller inputs (configuration)

| Input | Source | Default | Notes |
|-------|--------|---------|-------|
| `cut-off` | `workflow_dispatch` input | `30d` | Fallback `30d` on schedule. |
| `dry-run` | `workflow_dispatch` input | `true` | Ignored (forced delete) on `schedule`. |
| `image-name` | fixed in caller | `lfx-self-serve` | Exact single package; validated upstream. |
| `account` | shared default | `linuxfoundation` | Not overridden. |
| `enable-preview-protection` | fixed in caller | `true` | |
| `preview-label` / `preview-tag-prefix` | shared defaults | `deploy-preview` / `ui-pr-` | Must equal `docker-build-pr.yml` conventions. |

## Eligibility rule

A version is deleted iff:

1. `now - updated_at > cut-off`, and
2. none of its tags matches any protected tag pattern above, and
3. it is not a child manifest of a retained multi-arch parent, and
4. `dry-run` is false (always false for `schedule`).

Otherwise it is retained. In dry-run it is only reported as "Would delete".

## Run states

```text
trigger -> [preview-tags: skipped | success | failure]
        -> cleanup runs iff (!cancelled) and preview-tags in {success, skipped}
        -> summary written (always) -> exit 1 iff failed-count > 0
```

With preview protection enabled here, `preview-tags` must succeed for `cleanup` to run; a discovery failure yields no deletion.
