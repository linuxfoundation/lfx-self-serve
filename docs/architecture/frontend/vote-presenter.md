# Vote Presenter View

Full-screen, chrome-less view a chair uses to run a vote live (epic #4140). Route: `/votes/:id/present`.

**Location:** `apps/lfx-one/src/app/modules/votes/vote-presenter/`

## Route placement

The route is a **top-level sibling in `app.routes.ts`**, next to `meetings/:id` and the other chrome-less pages, before the in-shell `**` catch-all. It is deliberately not a child of `votes.routes.ts`: every child of the `votes` mount renders inside `MainLayoutComponent` (navbar and sidebar) and passes through `lensRedirectGuard`. `/votes/:id` (the permalink) is `pathMatch: 'full'`, so it never captures `/votes/:id/present`.

Guards: `authGuard`, then `votePresenterGuard`. Route data `preload: false`.

## Permission: `vote#writer`

`GET /api/votes/:uid?include_writer=true` decorates the vote with `writer` (the `vote#writer` FGA relation, via `AccessCheckService.checkSingleAccessStrict`, so an access-check outage fails the request instead of reading as `writer: false`). The flag is opt-in so existing callers and the 5-second polls pay no extra FGA lookup. `votePresenterGuard` reads it once per navigation (uncached) and the Present entry points read the same flag.

`writerGuard` is not reused: it checks project and committee writer, not `vote#writer`. On denial the guard redirects to `/votes?_notice=access` (the standard "Access Denied" toast, which also works on an SSR load); a transient lookup failure redirects with `_notice=error`.

## Data and secrecy

- The live count comes only from `GET /api/votes/:uid` (`num_response_received`, `total_voting_request_invitations`) through `computeVoteRowParticipation`; there is no second calculation.
- The voting service does not gate `/results` while a vote is open, so secrecy is enforced client-side: the presenter initially requests `/results` once per transition to `ended` (with bounded retries while results are held) and never calls `/voters`, `/reminder-recipients` or `/my-response`. No choices, tallies or voter names are rendered while the vote is open.
- `quorum_percentage` and `winning_threshold_percentage` are not in the `GET /votes/{uid}` payload, so the quorum marker is hidden and the ended banner is neutral ("Vote ended", or "Ranked result" for `isRankedPollType`). Approved / Not approved is never inferred.
- Close vote (#4143) ends an active vote through `POST /api/votes/:uid/end` (BFF: `assertVoteWrite`, then the voting service's `POST /votes/{uid}/end`; it keeps `end_time` and stamps `early_end_time`). It is enabled only while the vote is active (the route itself is writer-guarded) and always asks first through the standard confirm dialog. While the request is in flight the button stays disabled. On success the poll loop is restarted so the very next `GET /api/votes/:uid` decides the state: the presenter moves to the ended state only when that GET returns `ended`, and `/results` is then requested once, as for a vote that ended on its own. It is never faked with extend. A failure shows the upstream message in a toast and leaves the vote open. While the confirm dialog is open, Esc cancels the dialog and does not leave the presenter.
- Exit and Esc (#4691): while the phase is `active` or `reconnecting`, Exit opens the standard confirm ("Leave the presenter? The vote stays open.", Leave / Stay, Stay focused, backdrop click and Esc = Stay); on the ended, empty, error and loading screens it leaves at once. Esc with no dialog open is Exit. `confirmOpen` (Exit/Close) and the Send ballots child's public `confirming` signal (read through `viewChild`, so it is false once the child is destroyed) keep Esc from starting a second action; both reset a tick after the dialog hides so the Esc that closed it is still seen as "dialog open". Every confirmation binds its accept to the vote uid captured when it opened (`createGuardedConfirm`, and the same capture in `VoteSendBallotsComponent`): if the route has moved to another vote, the accept does nothing (no request, no toast). When a dialog hides, focus returns to the element that opened it; if that element is now disabled or gone (Close after Accept), it falls to the Exit button. That Exit/Close plumbing is `createGuardedConfirm` in `shared/utils/guarded-confirm.util.ts`; its types stay app-local beside it because they reference PrimeNG's `Confirmation` and `ConfirmationService`, which the framework-neutral `@lfx-one/shared` package must not import.
- Shared Close copy and row-menu Close (#4740): `VOTE_CLOSE_CONFIRMATION` (shared constants) feeds the presenter's Close dialog and the votes-table row menu, so the wording lives once. The table's accept is ignored when the row has left `votes()`; on success it overlays `ended` on the row (`closedVotes`, evicted once the index row stops saying `active`) and emits `voteClosed` so the dashboard refetches its counters. `VoteSendBallotsComponent` reads the voter list once per vote (browser only) so it can disable itself with "Everyone has voted"; a click re-reads it, and the info toast is kept only for a list that emptied since. A failed read toasts, opens no dialog and returns focus to the button after it re-enables.

## Visibility-aware polling

`createVisibilityPoll` (`shared/utils/visibility-poll.util.ts`) is the reusable poller: `timer` plus sequential `expand`, so requests never overlap. It fetches immediately and every `VOTE_PRESENTER_POLL_INTERVAL_MS`, cancels timers and in-flight requests while `document.visibilityState` is `hidden`, fetches immediately on `visible`, and retries failures on capped exponential backoff without ending the stream. `shouldContinue` can stop the loop and the next `visible` event restarts it, but the presenter does not use it: it keeps polling after `ended` so a vote another manager reopens or extends returns to the open state on the next tick, while `/results` is initially requested once per ended period. A `results_held` payload is retried every `VOTE_PRESENTER_RESULTS_HOLD_RETRY_MS`, up to `VOTE_PRESENTER_RESULTS_HOLD_MAX_ATTEMPTS` total requests. Retry failures retain the held payload and finalizing message, count toward that same limit, and never expose tallies or abstentions. An initial results failure still shows the results error. Reopening or changing votes cancels the held-results stream. Presenter polls use `fetchVote(id, { uncached: true })`, a cold request that is cancelled when the tab hides; the cached detail path's `shareReplay` is not ref-counted, so it would keep running and overlap the next show. A change of `:id` drops the previous vote's snapshot before polling the new one.

It is browser-only: the caller passes `DOCUMENT` and only subscribes when `isPlatformBrowser`. SSR renders the loading skeleton.

## Share panel and Copy slide

Link first: the large vote link and a Copy link button (Clipboard API, inline confirmation), then the QR. The QR is generated in the browser by `uqr` (MIT, zero dependencies), dynamic-imported inside `lfx-qr-code`, which draws the modules as one SVG path with `role="img"`. Copy slide renders the static `lfx-share-slide` artboard off-screen at 1920x1080 with `html-to-image` (dynamic import), copies the PNG with `ClipboardItem`, and falls back to a download named `<vote-slug>-vote-slide.png`. Title truncation (`truncateVoteTitle`, 80 characters, word-safe) is shared by the presenter and the slide.

The presenter is a composition of two shared primitives plus the vote-specific blocks. `lfx-presenter-share-panel` (`shared/components/presenter-share-panel`) owns the link, the Copy link button with its status and reset timer, a `[shareActions]` slot (Send ballots now and its hint are projected there), the QR code and the footnote. `lfx-presenter-shell` (`shared/components/presenter-shell`) owns the dark chrome-less frame, the phase switch, the LFX header and status pill, both footers (the open footer precedes the content in the DOM and is ordered last visually), and the loading and error screens; each phase's content is projected (`[presenterEmpty]`, `[presenterOpen]`, `[presenterEnded]`, plus `[footerActions]` for Close) and it emits `exit` and `retry`. Both render with `display: contents` hosts. The dialogs, Esc handling, focus return and the captured-vote rule stay in `VotePresenterComponent`; the shell provides nothing.

## Entry points

The votes-table row menu and the vote detail page header (**Present**) open the presenter in a new tab. The header shows the action to viewers with project or committee write access on an open or ended vote; the route's `votePresenterGuard` remains the authoritative `vote#writer` check, so the header's project/committee check only decides whether the action is shown.
