# One-off terminal result hook

A new one-off type can use `mktgOneOffTerminalFacts(rawPayloads)` and `mktgOneOffFailureText(facts)` from `@lfx-one/shared/server`. Valid envelopes win; only open questions after `currentTurnOffset` (the newest queued-turn marker) outrank current completion. Use `mktgOneOffTurnEnded(facts)` for terminal decisions: currentRootDone, or rootTaskEnded corroborated by nonblank current root reply text. Bare DONE metadata without a reply/completion after the marker stays pending; legacy error/session facts belong to Guild's recovery-aware outcome adapter, not this predicate. `MKTG_SESSION_TURN_STARTED` resets current terminal/text facts, while `MKTG_SESSION_EVENTS_TRUNCATED` suppresses all current terminal/text evidence for the capped page. The raw metadata walk precedes reasoning/feed filtering, but only current-root plain `agent_notification_message` string/data/text supplies a public-list reply; current roots require both `parent_task_id` and `parent_task` absent/null (Member's legacy predicate is unchanged); streams, progress, tool/child tasks and user bodies do not. The formatter selects bounded currentDoneText, then lastRootMessageText, then the shared fallback. Member 360 ignores the new current-turn facts and retains its runtime_done/session-end policy, contact redaction and classified fallback: error/failed evidence alone stays pending; a confirmed end with empty text uses the stopped fallback only when failed evidence is also present. LinkedIn failures persist on the next authorized read without a deadline wait; L1 projects the agent's failure prose only to its known creator, gives other readers the generic stopped message, and does not cache reader-specific LinkedIn terminal rows. Member's redacted text stays public. The existing Document failed card renders the projected text inside its collapsed Details disclosure; its heading, Try again and Check on it again actions and the one-off result header stay unchanged. This is a server-only adoption hook, not another browser pending mechanism.
